# BahaPredict Data Dictionary

This data dictionary describes the raw weather data retrieved from the Open-Meteo Historical Weather API and the processed rainfall dataset generated by the M3 transformation pipeline.

## 1. Raw Weather Dataset

The raw dataset contains the original JSON response returned by the Open-Meteo Historical Weather API.

| Field                           | Data Type     | Description                                                                                                                              |
| ------------------------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `latitude`                      | Float         | Latitude of the location returned by the Open-Meteo API.                                                                                 |
| `longitude`                     | Float         | Longitude of the location returned by the Open-Meteo API.                                                                                |
| `generationtime_ms`             | Float         | Time required by the API to generate the response, measured in milliseconds.                                                             |
| `utc_offset_seconds`            | Integer       | UTC offset of the requested timezone in seconds.                                                                                         |
| `timezone`                      | String        | Timezone used for the returned weather data.                                                                                             |
| `timezone_abbreviation`         | String        | Abbreviated timezone name.                                                                                                               |
| `elevation`                     | Float         | Elevation of the location in meters above sea level.                                                                                     |
| `daily_units`                   | Object        | Contains the units and date format used by the daily weather fields.                                                                     |
| `daily`                         | Object        | Contains the daily weather observations.                                                                                                 |
| `daily_units.time`              | String        | Format of the dates returned in the `daily.time` field.                                                                                  |
| `daily_units.precipitation_sum` | String        | Unit of measurement for daily precipitation. The value is `mm`.                                                                          |
| `daily.time`                    | Array[String] | List of dates for each daily weather observation in `YYYY-MM-DD` format.                                                                 |
| `daily.precipitation_sum`       | Array[Float]  | Total precipitation for each day, measured in millimeters (mm). Each value corresponds to the date at the same position in `daily.time`. |

## 2. Processed Rainfall Dataset

The processed dataset is generated by `scripts/transform.py` from the raw Open-Meteo API responses.

### Dataset Grain

One row represents **one daily rainfall observation for one representative geographic location within a Philippine administrative region**.

The current M3 dataset covers **17 Philippine administrative regions**, with one representative location used for each region.

### Identifier

The logical identifier for an observation is:

`date + latitude + longitude`

This allows the same date to exist for different geographic locations and regions.

| Field                   | Data Type | Description                                                                   |
| ----------------------- | --------- | ----------------------------------------------------------------------------- |
| `date`                  | Date      | Date of the rainfall observation. Stored in `YYYY-MM-DD` format.              |
| `region`                | String    | Philippine administrative region associated with the representative location. |
| `location`              | String    | Representative location used for the weather observation.                     |
| `latitude`              | Float     | Latitude returned by the Open-Meteo API for the observation location.         |
| `longitude`             | Float     | Longitude returned by the Open-Meteo API for the observation location.        |
| `precipitation_mm`      | Float     | Total daily precipitation measured in millimeters.                            |
| `precipitation_missing` | Boolean   | Indicates whether the precipitation value was missing during transformation.  |
| `is_extreme`            | Boolean   | Indicates whether daily precipitation is at least 50 mm.                      |

## 3. Data Cleaning and Transformation Rules

The M3 transformation process applies the following cleaning rules:

1. The nested `daily` API structure is flattened into one row per daily observation.

2. `daily.time` values are converted to date values.

3. `daily.precipitation_sum` values are converted to numeric values.

4. Invalid dates are removed from the processed dataset.

5. Missing precipitation values are flagged using `precipitation_missing`.

6. Missing precipitation values are not automatically replaced with `0`, because missing rainfall data does not necessarily mean that no rainfall occurred.

7. Duplicate observations are removed using `date`, `latitude`, and `longitude`.

8. Negative precipitation values are rejected during validation because rainfall cannot have a negative value.

9. The `is_extreme` field is calculated using the project threshold of 50 mm/day.

10. The processed dataset is saved as `data/processed/rainfall_clean.csv`.

## 4. Data Validation Rules

The transformation pipeline performs the following validation checks:

* Required columns must exist.
* Dates must be valid.
* Precipitation values must be numeric.
* Precipitation values must not be negative.
* Duplicate observations are not allowed.
* `is_extreme` must correctly identify precipitation values greater than or equal to 50 mm.
* The transformation must complete successfully before the processed dataset is saved.

* **Unit:** millimeters (mm)

## 7. Business Analysis Fields

The processed dataset supports the following M3 business analysis:

### Extreme Rainfall

`is_extreme` identifies daily rainfall observations of **50 mm/day or greater**.

This field is used to determine the number of extreme rainfall days by region and representative location.

### Monthly Average Rainfall

Monthly average rainfall is calculated from `precipitation_mm` across the processed observations.

This helps identify months with higher average rainfall across the 17 regions.

### Total Rainfall by Region

Total rainfall is calculated by summing `precipitation_mm` for each representative location and region.

This provides a comparison of cumulative rainfall across the 17 regions during the study period.

## 8. Notes

* The raw API responses are preserved without modification in `data/raw/`.
* The processed dataset is generated by `scripts/transform.py`.
* The latitude and longitude stored in the processed dataset are the coordinates returned by Open-Meteo, which may differ slightly from the requested coordinates because the API returns the location associated with its weather data grid.
* `daily.time` and `daily.precipitation_sum` are positionally related in the raw API response.
* The current ingestion implementation retrieves rainfall data for one representative location for each of the 17 Philippine administrative regions.
* The representative location approach provides regional coverage for the M3 pipeline while keeping the dataset manageable.
* The 50 mm/day extreme rainfall threshold is a project-specific analytical definition and may be refined using official meteorological guidance in future iterations.
* The current dataset covers January through August 2026 and can be extended to additional dates in future pipeline runs.
